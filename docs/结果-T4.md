# T4 结果 · M0 端到端手工验证（2026-09-10）

> 目的：手工串「VAD 定界 → 段级打标 → 语音段 ASR → 组装 digest」，把 digest 交给一个**隔离的模型实例**盲测，看它能否只凭 digest 选对工具、指对时间段。产出是 **digest schema 定稿**。
> 脚本：`tools/t4_build_digest.py`
> 素材：`testdata/m0_hum_then_speech.wav`（4.4s：00:00–02:00 合成哼唱 + 02:00–04:00 TTS 口述「帮我把这段的谱子扒出来」）
> 机器：MacBook Air M1 / 16GB，CPU，4 线程；全 ONNX（sherpa-onnx），零 torch

## 管线

1. **VAD 定界**：Silero VAD（`min_silence_duration = 0.25`，`min_speech_duration = 0.25`）切出语音段；语音段之间的空隙作为非语音段，得到交替的时间轴。
2. **段级打标**：对每个段各跑一次 clip 级 AudioSet tagger（Zipformer int8，27MB），取 top-3。
3. **语音段 ASR**：只对语音段跑 SenseVoiceSmall int8。
4. **组装 digest**：确定性模板，无 LLM 参与。`gaps` 由规则生成：非语音段写"只知类别不知内容"；若非语音段在前、语音段在后，写一条结构提示。

## 盲测

方法：开一个**隔离的模型实例**（没有本项目任何上下文），只给它上面的 digest 和 `capabilities_available` 里 7 项能力的一句话说明，问它：要处理哪个时间段、调哪个能力、缺什么。

### 盲测原文（复核后）

隔离实例的完整回答要点：

> - 主选 `pitch_transcribe`；可选搭配 `chord_recognize`；**不选** `transcribe_segment`（那是转语音文本，段 2 的 ASR 已经给过，对"扒谱"无用）
> - 时间范围 **0.00–2.182s**：指令出现在第二段（纯语音，ASR 已确认只是一句指令），**它本身没有可扒的音高内容；被指代的"这段"只能是前面的非语音段**
> - "digest `gaps` 也已明确提示这个『非语音在前、指令在后』的指代风险"
> - "一句话：这份 digest **够用来『选工具』（指向引导正确），但不够用来『真正扒谱』**"
> - 并自行指出 `labels` 分数整体在 0.1 量级属于不可靠信号，不宜据此断言第一段为音乐

**判定：通过（n=1）。** 选对工具、指对时间段、主动排除了无关能力、没有被低分标签误导。

## 四条观察 → schema 修正

**① `gaps` 是核心字段，不是装饰。** 盲测实例正是靠 `gaps` 里那条"非语音在前、指令在后"的结构提示做对了判断。这条提示是任务无关的结构事实（不是"你应该扒谱"），符合铁律 2。→ `gaps` 必须由规则稳定生成，不能依赖打标质量。

**② 低置信度不下结论。** 原始输出把 `Boing:0.118` 当成第一段的标签写进了 `gaps`，盲测实例自己识破了。但不该让下游来识破。→ 设 `label_confidence_threshold`（拟 0.30）；低于阈值时 `labels: []`、`label_status: "unclassified"`，并在 `gaps` 里写"分类置信度过低（top 0.118 < 阈值 0.30）→ 无法判定类别"。**禁止把 0.118 分的标签当事实。**

**③ `null` 的语义要收紧。** 原始输出里 `asr.confidence: null` 和 `global.caption: null` 是"取不到"，`segments[0].asr: null` 是"不适用"，两种含义混用。→ `null` 只表示"该字段对本段不适用"；取不到的值用 `"n/a"` 或省略；"不知道"一律走 `gaps`。便宜档没有 captioner，所以 **`caption` 字段直接去掉**，需要描述时它是 `capabilities_available` 里的一项可选能力。

**④ 预检只负责"路由"，不供给"执行数据"。** 盲测列出的"缺失信息"里有：音高 / 音名、调性、速度、单音或复音、乐器、调音基准。**这些不该进 digest。** 它们是被调用能力的执行产物，不是预检的判断依据。→ schema 要明确这条边界：digest 唯一必须交给下游的是**原始媒体引用**。盲测原话"够用来选工具，但不够用来真正扒谱"，正是应有的边界。

修正后的 schema 见 [架构.md §8](架构.md#8-digest-schema核心产出物)。

## 结论

1. **D4 验证通过**："够不够 / 下一步做什么"的判定权归上层 agent 是可行的：不猜意图、只给结构事实，agent 能自己推出指代关系。
2. **确定性模板够用**：VAD + 打标 + ASR 的输出直接按 schema 组装，不需要精炼层。
3. **`capabilities_available` 给全量 7 项可行**：盲测正确分出了主选 / 可选 / 排除，token 成本可接受。
