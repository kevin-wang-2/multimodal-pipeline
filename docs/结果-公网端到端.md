# 结果 · 公网端到端与零监听验收（2026-09-21，S4 / S5 收口）

> 对应 [实施计划.md](实施计划.md) §1 M1 定义第 2、5、6 条与 S4 / S5 的公网验收项。S6 写 `结果-M1.md` 时并入。

## 拓扑

```
公网 agent 宿主 = 枢纽机（Ubuntu 24.04，阿里云 HK）           内网 GPU 机（Windows，公司 NAT 后，出口 114.92.209.87）
  nginx 443 (TLS, certbot)  ──反代──▶ B-ts 127.0.0.1:8766      A = mmp_broker.main（B-py 绑定 127.0.0.1:8765）
  域名 mmp.seanartech.com / mmp.clickinmusical.com    ◀── wss ── A 主动出站，register / 心跳 / 收 request
  任务 API 与 /ws 共用 443；api_key 保护任务 API                 引擎子进程：echo、triage.audio、ocr.structured
```

- 阿里云安全组只放 22 / 80 / 443，所以 B-ts 不直接暴露端口，走 nginx（`/etc/nginx/sites-available/mmp`，证书 certbot 管理，`proxy_read_timeout 300`）。B-ts 由 PM2 常驻（`mmp-broker`，配置 `~/mmp/broker.toml`，密钥只在该机与 A 机）。
- A 的配置 `C:\mmp\node.toml`：`[[brokers]] url = "wss://mmp.seanartech.com/ws"`；三个引擎各自解释器。

## 结果

### A↔B（M1 第 5、6 条，S4）

| 项 | 结果 |
|---|---|
| A 在 NAT 后连到公网 B-ts，`/health` 显示 `gpu-lab`、心跳含 `vram_free_mb: 16303` | ✅ |
| 公网侧 `POST /jobs` echo 往返 | ✅ 200，`total 61 ms` |
| A 进程的监听套接字 | 仅 `127.0.0.1:8765`（绑定模式 B-py）；引擎子进程无监听 |
| A 的出境连接 | 仅 `→ 47.243.12.173:443`（wss） |
| 从枢纽机 nmap A 机出口 IP：1–1024、2222、3389、5000–9000、18765 共 5028 端口 | **0 open**（全部 filtered） |
| 停 A → B `/health` 变 `no_node`；重启 A → 自动重连重注册 | ✅（拔线 / 重启 B 的在途 503 与退避重连在 `node/tests/test_ws_integration.py` 自动化） |

### 公网端到端（M1 第 2 条，S5）

枢纽机模拟宿主签发句柄：`https://mmp.seanartech.com/_media/<token>/in/<f>`（GET）与 `/out/<f>`（PUT），token 不对 403（测试后已拆除）。素材：合成文档页（无真实数据）与 M0 音频。

| 任务 | 句柄 | 结果 | 耗时 |
|---|---|---|---|
| `triage.audio` | get + put | 200，digest 两段、切点 1.984 | wall 2.7 s（fetch 0.9 s 跨境 GET） |
| `ocr.structured` gpu-fast | get + put | 200，8 行、mean_score 0.98、coverage 1.00、无 flag | wall 8.2 s（含引擎冷启） |
| `ocr.structured` gpu（VL） | **ref** + put | 200，`fetch 0 ms`——没有二次下载 | wall 3.9 s |
| 把 A 内联上限压到 512 B 重跑三条（换参数避开缓存） | put | 三个结果均以 `result_ref` 返回，PUT 到枢纽机的文件字节数与 ref 一致 | fetch 1.9–2.7 s |
| 重启 A 后重提同参数 | — | 三条全部 `cached: true`（SQLite 缓存跨重启） | 0.1–1.7 s |

### 观察

- 跨境 GET 一次 0.9–2.7 s，是这条链上最大的可变成本；`ref` 命中后为 0——v1.1 的媒体引用在公网路径上价值最直接。
- 缓存命中的结果按缓存时的形态（内联）交付，不看当前内联上限——合理，但意味着"结果去哪"由首次计算决定。
- nginx 反代下 A 的 ws 靠 `ping_interval 20s` 与应用层 10 s 心跳保活，`proxy_read_timeout 300` 足够。
