# T3 结果 · AED 时序路由验证（2026-09-10）

模型：`sherpa-onnx-zipformer-small-audio-tagging-2024-04-15`（AudioSet 类，**ONNX，无 torch**）
用法：模型本身是 **clip 级**（无时序定位），我们用**滑窗**得到伪帧级置信度曲线——正是路由需要的形状。
脚本：`tools/t3_aed_routing.py`（1.0s 窗 / 0.2s 步进 / int8 模型）

## 结果（4.4s 素材：00:00–02:00 哼唱 + 02:00–04:00 口述）

| 起点 | 顶部标签 |
|---|---|
| 0.00 | Music:0.52  Synthesizer:0.19  Musical instrument:0.09 |
| 0.40–1.60 | Dog / Bow-wow / Animal / **Sound effect**（**无 Speech**） |
| 1.80 | Sound effect:0.43  **Speech:0.11**（开始抬头） |
| **2.00** | **Speech:0.95** ← |
| 2.20–3.20 | Speech:0.84 / 0.52 / 0.65 / 0.37 / 0.23 / 0.89 |

**检测到的 Music→Speech 交叉点 ≈ 1.80s（真值 2.00s，误差 = 一个步进）** ✅

## 结论

1. **边界检测有效**：Speech 置信度在真值边界处从 ~0.1 跳到 0.95，交叉点误差不超过一个 hop。路由决策（送不送 ASR）可以靠这条曲线做。
2. **速度很好**：**27 ms / 窗**（1s 窗，int8，4 线程）→ 约 **37× 实时**，纯 CPU、无 torch、模型仅 27MB。
3. ⚠️ **细粒度标签在合成音频上不可信**：我们的正弦哼唱被标成 `Dog`/`Bow-wow`。
   这是**合成素材的产物**（纯正弦音不像真实人声哼唱），但也说明一条设计原则：
   **路由只能用粗类别 + 置信度，不要过度信任细标签**；且必须用**真实音频**复验。
4. ⚠️ **别用密集滑窗做长音频**：1 小时音频 × 0.2s 步进 = 18000 窗 × 27ms ≈ **8 分钟**。
   正确做法（与设计稿一致）：
   - **边界** → 便宜的 VAD（Silero，帧级）——whisper.cpp 内置 VAD 切在 **1.99s**（几乎完美）
   - **打标** → 对 VAD 切出的**段**各跑一次 clip 级 tagger（次数 = 段数，不随时长线性增长）

## 三方对照（同一边界，不同方法）

| 方法 | 切点 | 成本 |
|---|---|---|
| whisper.cpp 内置 Silero VAD | **1.99s** | ~7 ms / 4.4s |
| sherpa-onnx Silero VAD | 2.18s（偏晚，吞字，需调 padding） | ~45 ms / 4.4s |
| 滑窗 AudioSet tagger（本测试） | 1.80s | ~0.5s / 4.4s（27ms/窗） |

→ **推荐的 L0 组合：Silero VAD 定边界 + 段级 tagger 打标**，而不是密集滑窗。
