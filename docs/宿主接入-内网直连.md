# 宿主接入 · 内网直连（`@mmp/client` → A/B 绑定的 B-py）

> 面向**世纳终端 agent**这类情况：宿主和算力节点 A 在同一内网 / tailnet，用 TypeScript 直接调 `@mmp/client`，不经过公网枢纽，也不用 OpenClaw 插件。和 [接入指南.md](接入指南.md)（公网、production manager）的差别只在**连哪个 B、地址能不能是内网、失败长什么样**三处；API、任务类型、规则完全一样，本文不重复那些内容，只讲差异和一份可直接抄的接法。

## 0. 三种宿主怎么连

| 宿主 | 网络 | 连哪个 B | 接法 |
|---|---|---|---|
| production manager | 公网 | 枢纽机 B-ts `https://mmp.seanartech.com` | [接入指南.md](接入指南.md) |
| OpenClaw（本机） | 内网 | GPU 机上的 B-py | [宿主接入-OpenClaw.md](宿主接入-OpenClaw.md)（cli 条目 + 钩子） |
| **世纳终端 agent** | **tailnet / 内网** | **GPU 机上的 B-py** | **本文：直接 `@mmp/client`** |

B-py 是与 A 绑定在同一进程里的协调节点：无状态、同一套任务 API、同一套 `@mmp/protocol` 契约测试。对宿主来说它和公网 B-ts 是同一个接口，只是地址和证书不同。

```
世纳终端 agent（ts）──@mmp/client──▶ http://100.64.0.5:8765（B-py，同一进程内就是 A）──▶ 引擎子进程
                       tailnet 或本网段；api_key；A 零公网监听
```

## 1. 安装

同公网：

```ini
# 项目根 .npmrc（可提交）
@mmp:registry=https://mmp.seanartech.com/npm/
```

```bash
pnpm add @mmp/client
```

registry 匿名可读。`@mmp/client` 的 README 里有完整 API。

## 2. 配置（与公网不同）

| 变量 | 值 | 说明 |
|---|---|---|
| `MMP_BASE_URL` | `http://100.64.0.5:8765`（tailnet）或 `http://192.168.71.200:8765`（与 GPU 机同网段时） | 明文 http；tailnet 上由 WireGuard 加密，同网段是内网明文——不要把这个地址写进任何会离开内网的配置 |
| `MMP_API_KEY` | B-py 的 `api_key`，在 GPU 机 `C:\mmp\node.toml` 的 `[broker]` 段 | 由维护者单独给；不进仓库。`/health` 不要 key，其余全部 401 |

宿主机要满足其一：在 tailnet 里（GPU 机防火墙对 `100.64.0.0/10` 放行 8765），或与 GPU 机同一网段（`LocalSubnet`）。**境外机器不进 tailnet**，这条不动。

先验证：

```bash
curl http://100.64.0.5:8765/health
# {"status":"ok","protocol_version":"1.2","nodes":[{"node_id":"gpu-lab",…}]}
curl -H "Authorization: Bearer $MMP_API_KEY" http://100.64.0.5:8765/capabilities
# echo / triage.audio / ocr.structured
```

## 3. 接法（可直接抄）

一个附件一次预检，结果作文本注入；同一附件后续全部用 `ref`；服务不可用时显式标注降级并走自己的兜底。

```ts
import { MmpClient, MmpError, media, renderDigest, renderUnavailable } from "@mmp/client";
import type { JobDone } from "@mmp/client";

const mmp = new MmpClient({
  baseUrl: process.env.MMP_BASE_URL!,        // http://100.64.0.5:8765
  apiKey: process.env.MMP_API_KEY,
});

// 每个附件只预检一次。key 用你自己的附件 id；value 记 media_id 与注入块，多轮追问直接复用，不再提交。
const seen = new Map<string, { mediaId: string; block: string }>();

export async function triageAttachment(
  attachmentId: string,
  bytes: Uint8Array,
  contentType: string,                       // audio/mp4、audio/wav、audio/ogg… 服务端 ffmpeg 转码，任意采样率 / 声道
  fallbackTranscript?: string,               // 你平台自己的转写（如果有），降级时给主模型
): Promise<string> {
  const hit = seen.get(attachmentId);
  if (hit) return hit.block;

  try {
    const done: JobDone = await mmp.run(
      { type: "triage.audio", media: media.inline(bytes, contentType), priority: "interactive" },
      { pollWaitSec: 30, timeoutMs: 60_000 },
    );
    const block = renderDigest(done.result);   // 确定性模板，[mmp:digest start] … [mmp:digest end]
    seen.set(attachmentId, { mediaId: done.media_id, block });
    return block;
  } catch (e) {
    if (e instanceof MmpError && e.shouldFallback) {
      // A 停机 / 不可达 / 队列满 / 引擎失败：不要静默。这行告诉主模型"这次没有时间轴、事件类型和缺口信息"。
      return renderUnavailable(e.code, fallbackTranscript);
    }
    throw e;                                   // bad_request / media_too_large 之类是你的问题，抛出去
  }
}

// 后续任务用 ref：不重传字节。ref 过期（media_not_found）时 refOr 会带上完整句柄重提。
export async function ocrAttachment(attachmentId: string, bytes: Uint8Array, contentType: string, pages?: number[]) {
  const mediaId = seen.get(attachmentId)?.mediaId;
  const handle = mediaId ? media.refOr(mediaId, media.inline(bytes, contentType)) : media.inline(bytes, contentType);
  return mmp.run({ type: "ocr.structured", media: handle, params: pages ? { pages } : {} }, { pollWaitSec: 30 });
}
```

注入：`prompt = block + "\n\n" + userMessage`。块里的 `⚠` 行与 `degraded=` 保留给主模型看，不要再让 LLM 总结这个块。

## 4. 与公网接法的三处差异

1. **`get` 句柄可以是内网 / tailnet 地址**。公网指南说"必须公网可达"，是因为算力节点在别的网络；这里 A 就在你旁边，`media.get("http://100.64.0.x/…")` 它拉得到。> 8 MiB 的媒体走这条。A 侧不走系统代理（`use_env_proxy = false`），地址要能从 GPU 机直接解析、直接连。
2. **"节点离线"长得不一样**。B-py 与 A 同进程，A 停了整个端口就没了：你拿到的是 `MmpError.code === "network"`（连接被拒 / 超时），不是公网那种 `503 no_node`。两者 `shouldFallback` 都是 true，上面的接法已经覆盖。A 由 GPU 机上的计划任务 `mmp-node` 常驻，开机自启；停了找维护者。
3. **没有 TLS**。tailnet 上不需要；同网段明文——只在内网用，不要把 `MMP_BASE_URL` 指到任何经公网的路径。

其余（任务类型表、`MmpError` 分类、`ref` / 缓存、`wait` 上限 120 s、大结果 `put`）与 [接入指南.md §4–§6](接入指南.md) 完全相同。

## 5. 多轮与降级的行为约定

- **同一媒体连续追问不重复推理**：上面 `seen` 就是为这条；即使你没记，服务端也按 `media_id + type + tier + params` 命中缓存（`cached: true`），只是多一次上传。
- **降级必须显式**：`renderUnavailable(code, fallbackTranscript)` 输出的 `[mmp:digest unavailable]` 块告诉主模型这次只有平台转写（或什么都没有）。不允许在 A 停机时让主模型误以为拿到了预检结果。
- **交互式优先**：用户当场发的附件用 `priority: "interactive"`；后台批量（整理历史消息、批量 OCR）用 `"batch"`。批量排队 200 个时交互式仍在 2 s 左右完成；队列满返回 `429 backpressure`（`retry_after_sec`），客户端会自动重试一次，再失败就是 `shouldFallback`。

## 6. 排障

| 现象 | 原因 |
|---|---|
| `network: fetch failed` / `ECONNREFUSED` | A 没在跑（GPU 机 `schtasks /Query /TN mmp-node`），或宿主不在 tailnet / 不在同网段（防火墙只放这两类来源） |
| `401 unauthorized` | `MMP_API_KEY` 不对；`/health` 不验 key，所以"health 通、jobs 401"就是这个 |
| `/health` 里 `nodes: []` 或 `status: no_node` | 只会在公网 B-ts 出现；B-py 与 A 同进程，要么整个不通、要么 `ok` |
| 连得上但很慢 | 宿主机的代理 / TUN（如 Clash）把 `100.64.0.0/10` 或内网段劫持了：给这些网段加直连规则。Node 的 `fetch` 不读 `HTTP_PROXY`，问题只可能在系统层 |
| `media_too_large` | 内联 > 8 MiB：改 `media.get(内网 URL)` |
| `media_not_found` | `ref` 在服务端已被 LRU 淘汰：`media.refOr(id, 完整句柄)` |

## 7. 现在能用的任务类型

同 [接入指南.md §4](接入指南.md)：`triage.audio`（CPU，4 s 音频 ≈ 1–2 s）、`ocr.structured`（`gpu-fast` ≈ 1 s/页；`tier: "gpu"` ≈ 4–9 s/页，单卡串行）、`echo`。digest 里的 `capabilities_available` 目前是清单，M2 起按名可调（`pitch_transcribe` 等），接法不变：都是 `mmp.run({ type, media: media.ref(mediaId), params })`。
