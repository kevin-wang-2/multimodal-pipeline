# 接入指南：在 agent 宿主里使用 multimodal-pipeline

> 面向要把多模态预检接进自己服务的工程师（首个目标：click-in production manager）。
> 协议细节见 [协议.md](协议.md)，设计背景见 [架构.md](架构.md)；本文只讲"怎么接、要遵守什么"。

你要接的是一个**多模态感知服务**：把音频 / 文档交给它，拿回一段结构化 digest（时间轴 + 原子事实 + 缺口 + 可用能力清单），作为**文本**注入给主模型。服务入口是 `https://mmp.seanartech.com`（B 协调节点）；算力节点在别处，你不需要知道它在哪。

## 1. 安装

项目根 `.npmrc` 加一行（可以提交进仓库），然后装包：

```ini
@mmp:registry=https://mmp.seanartech.com/npm/
```

```bash
pnpm add @mmp/client        # npm / yarn 也一样
```

registry 匿名可读，不需要凭据。包内自带 README（`node_modules/@mmp/client/README.md`），API 全在里面。

## 2. 配置

两个环境变量，放部署环境 / secret，**不要进仓库**：

| 变量 | 值 |
|---|---|
| `MMP_BASE_URL` | `https://mmp.seanartech.com` |
| `MMP_API_KEY` | 由维护者单独提供（B 的 api_key） |

## 3. 核心用法

```ts
import { MmpClient, MmpError, media } from "@mmp/client";

const mmp = new MmpClient({ baseUrl: process.env.MMP_BASE_URL!, apiKey: process.env.MMP_API_KEY });

// 按 purpose + MIME 发现预检能力；不在宿主里硬编码模态或任务 id
let context: string;
try {
  const capability = await mmp.resolveCapability({ purpose: "triage", contentType: attachment.type });
  const done = await mmp.run(
    { type: capability.id, media: media.inline(bytes, attachment.type) },
    { pollWaitSec: 30 },
  );
  context = done.agent_context!.text;           // 任务端产出，client 只透传
  mediaIdByAttachment.set(attachmentId, done.media_id);   // 记下 media_id，后续用 ref
} catch (e) {
  if (e instanceof MmpError && e.shouldFallback) {
    // 服务不可用：显式标注降级，用平台自己的转写兜底。主模型必须知道这次没有时间轴信息。
    context = explicitHostFallback(e.code, platformTranscript);
  } else {
    throw e;
  }
}
prompt = context + "\n\n" + userMessage;

// 同一附件的后续任务用 ref：不再上传
await mmp.run({ type: "ocr.structured", media: media.ref(mediaId), tier: "gpu", params: { pages: [2] } });
```

## 4. 现在可用的任务类型

| `type` | 输入 | 主要 `params` | 输出 | 耗时量级 |
|---|---|---|---|---|
| `triage.audio` | WAV / m4a / mp3 / ogg / flac / amr（服务端 ffmpeg 转码；任意采样率 / 声道） | `label_confidence_threshold`（默认 0.30）、`language`（auto / zh / en / ja / ko / yue） | digest：`segments[]`（`[start, end)` 秒、标签、语音段 ASR）、`gaps[]`、`capabilities_available[]` | 4 s 音频 ≈ 1–2 s |
| `ocr.structured`（默认 `gpu-fast`） | PDF / PNG / JPEG / TIFF / WEBP | `pages`（1-based）、`lang`（ch / en）、`dpi`（200） | `pages[].text / lines[] / quality / flags`，`suggest_upgrade_pages` | ≈ 1 s/页 |
| `ocr.structured` + `tier: "gpu"` | 同上 | 同上 | 另加 `markdown` 与 `elements[]`（`table` / `seal` / `text` …） | ≈ 4–9 s/页，单卡串行 |
| `echo` | 任意 | `sleep_ms`、`tag` | 回显 hash 与 params | ms（联调用） |

OCR 的"要不要上慢档"由你决定：快档结果里某页 `flags` 非空（`low_confidence` / `coverage_anomaly` / `empty`）、`suggest_upgrade_pages` 有页时，再提一个 `tier: "gpu"` + `params.pages` 的任务。服务不会自动升级。

## 5. 必须遵守的规则

1. **媒体句柄只有三种**：`inline`（base64，≤ 8 MiB）、`get`（带认证的 URL，**必须公网可达**——算力节点在别的网络，你的内网地址它拉不到）、`ref`（此前任何响应里的 `media_id`）。没有本机路径。
2. **大结果**：给句柄加 `media.withPut(handle, 你签发的 PUT URL)`，超过 1 MiB 的结果会 PUT 过去，响应里只有 `result_ref`。OCR 单页一般几 KB，不会触发；先不接也行。
3. **失败一律是 `MmpError`**：
   - `code` 是协议错误码（`no_node` / `node_offline` / `backpressure` / `engine_failed` / `timeout` / `media_not_found` …）或传输层 `network` / `timeout` / `unexpected`；
   - `retryable` 的情形客户端已自动重试（默认 2 次，只对未入队的请求和读操作）；
   - `shouldFallback` 为 true 时走你的兜底并由宿主显式标注——**不要静默吞掉**；
   - `media_not_found` 表示 `ref` 已在服务端过期：带完整句柄重提（`media.refOr(id, media.get(url))`）。
4. **同一附件不要重复提交完整媒体**：记住 `media_id`，后续用 `media.ref`。同样的媒体 + 类型 + 参数会命中服务端缓存（`cached: true`），不重复推理。
5. **注入块是确定性模板，不要再让 LLM 总结它**。`degraded=…` 与 `⚠` 行表示结果不完整，保留给主模型看。
6. `wait` 上限 120 s；`run()` 已封装长轮询，不用自己 sleep。

## 6. 先验证连通

```ts
console.log(await mmp.health());          // { status: "ok", nodes: [{ node_id: "gpu-lab", … }] }
console.log(await mmp.capabilities());    // echo / triage.audio / ocr.structured
```

`status: "no_node"` 表示算力节点离线，找维护者；`401` 表示 `MMP_API_KEY` 不对。

## 7. 注入块长什么样

```
[mmp:agent-context start]
media=sha256:… kind=audio duration=4.39s engine=silero-vad+sensevoice-int8+zipformer-tagging-int8 tier=cpu degraded=no
时间轴（秒，[start,end)）：
- [0.00, 1.98) 非语音：Music 0.78, Synthesizer 0.68
- [1.98, 4.39) 语音：「帮我把这段的谱子扒出来。」 (zh)
缺口：
- 0.00–1.98s 为非语音段（Music、Synthesizer），只知类别、不知内容（无音高 / 谱面 / 歌词）
- 结构事实：非语音段位于时间轴前部、语音段在后（指令在后）
可用能力：pitch_transcribe, chord_recognize, source_separate, denoise, speaker_id, music_id, transcribe_segment
[mmp:agent-context end]
```

`capabilities_available` 里的能力目前是清单（M2 起可以按名调用）；`gaps` 是主模型判断"信息够不够"的主要依据。
