# T6 结果 · 真实音频复验（进行中）

> 对应 [实施计划.md](实施计划.md) S2 并行项 / issue #4：M0–S2 的音频结论全部建立在合成素材（TTS + 正弦哼唱）上，这里用真人录音逐段复验。目标 n ≥ 10，盲测 n ≥ 10。
> 每个样本记：录音条件、原文、`triage.audio` 的 digest 摘要、暴露的问题、由此改的规则。素材不进仓库。

## 样本 #1 · 口哨 + 口述指令（2026-09-21）

- **条件**：手机录音 m4a（AAC 48 kHz 单声道），26.3 s，室外，有风噪与喷麦。先吹约 17 s 口哨，再口述指令。
- **原文**：「帮我把前面这段 呃 口哨吹出来的音频给变成谱子 谢谢」
- **链路**：`@mmp/client` → 公网枢纽 B-ts → 内网 A（ffmpeg 转 16k WAV）→ `triage.audio`（cpu）。

### 结果（engine_version 2026-09-21）

| 段 | 打标 | ASR |
|---|---|---|
| 0.00–0.61 | 无法判定（top 0.16） | — |
| 0.61–1.09 | Sound effect 0.62 | 「.」→ **gaps 标注不可靠**（Speech 分数 0） |
| 1.09–1.95 | Whistling 0.91 | — |
| 1.95–2.24 | 无法判定（Whistle 0.23） | 「あ.」→ **gaps 标注不可靠** |
| 2.24–18.59 | **Whistling 0.957** | — |
| 18.59–24.86 | **Speech 0.999** | **「帮我把前面这段呃口哨吹出来的音频给变成谱子，谢谢。」**（逐字对，含"呃"） |
| 24.86–26.30 | 无法判定 | — |

结构事实：非语音在前、指令在后 ✅。耗时（lab，CPU）：transcode 15 / vad 63 / tagging 203 / asr 108 ms。

### 观察

1. **真实口哨的打标可靠**：`Whistling 0.95`。合成哼唱当年是 `Boing 0.12`——T3 "合成哼唱标签不可信"的结论是素材的问题，不是模型的问题。
2. **ASR 在风噪 + 喷麦下逐字正确**，连填充词"呃"都保留。SenseVoice int8 便宜档在真人中文上成立。
3. **VAD 的假阳性是主要噪声源**：喷麦 / 呼吸 / 口哨起音会被 Silero 判成 0.3–0.5 s 的"语音"，SenseVoice 对着它们幻觉出一两个词（"Yeah." / "." / "あ."）。三次全部发生在非语音事件的边缘。
4. **同一段音频，afconvert 与 ffmpeg 解码的样本略有差异**，让处在阈值边缘的 VAD 决策翻转（一次把指令句在 22.59 处切成两半、一次在口哨起音多切出一段）。切分对边界样本不稳定是常态，规则不能依赖"切得恰好"。

### 由此改的规则

- **`asr.confidence` = 打标里 `Speech` 的分数**（SenseVoice 不给置信度）。真语音 0.99+，幻觉段 0。低于 `label_confidence_threshold` 的进 gaps："被 VAD 判为语音，但打标未见 Speech（top …）→ ASR 文本「…」不可靠，可能是喷麦 / 呼吸"；注入块里标"语音（低置信）"。文本**保留**，不删——判断交给上层。
- **不合并被短间隔切开的语音段**。曾实现"间隔 < 0.5 s 合并为句内停顿"，但合并发生在打标之前，会抹掉夹在两句话之间的短事件（"听听我的绝对音感准不准 [一声口哨] 这个是 A 吧"）。改为 gaps 里点出"X–Ys（NNN ms，标签）夹在两段语音之间——可能只是停顿，也可能是有内容的短事件"。
- **A 侧音频转码**：m4a / mp3 / ogg / flac / amr / aiff / webm 经 ffmpeg 转 16 kHz 单声道 WAV 再给引擎；`media_id` 仍是原始字节的 hash。手机录音默认就是 AAC，没有这条真实素材进不来。

### 未解决

- VAD 假阳性本身（喷麦 / 起音被判语音）没有在 VAD 层修，只是在后面识破并标注。候选：Silero v5、把打标 Speech 分数反馈给 VAD 做二次判定。
- 语音段**终点**在合成哼唱上晚 130–230 ms（S2 记录）在真实素材上未复现明显问题；本样本指令句末尾 24.86 与听感一致。

## 样本 #2–#10 · 一批手机录音（2026-09-21）

同一说话人，手机 m4a，室内。文件名即原文。链路同 #1；engine_version 2026-09-21b。

| # | 素材 | ASR（语音段） | 非语音 / 短事件 | 备注 |
|---|---|---|---|---|
| 2 | 「你好，这是一段指令」6 s | 「你好。」「这是一段指令。」 ✅ | 句间 351 ms 停顿被点出 | 纯语音基线干净 |
| 3 | 「Hey buddy, this is Captain speaking」3.6 s | ✅ lang=en | — | 英文 |
| 4 | 中英混：「帮我解释一下 X 在中文到底应该怎么念，我只会英文」7 s | 中文全对，英文名按音转写 | — | `language: auto` |
| 5 | 「后面我哼一段歌，听听这个歌在不在调上 [哼唱]」9.8 s | 前半对，后半「看看这个歌我恨没哼的掉上」**错** | 哼唱段 VAD 判语音、打标 `Mantra 0.68`、ASR 幻觉「哒啦哒哒」→ 低置信标注 | 口语快速连读处 ASR 出错；哼唱被识别为"非语音但有内容"靠的是打标而非 VAD |
| 6 | 「听一下这个音是什么音高 [la] 就是这个」5.9 s | 「听一下这个音是什么音高。」✅ ；「就是这个。」✅ 但被标低置信 | 唱的 la：`Music 0.45 / Humming 0.40`，幻觉「あ。」→ 低置信标注 ✅ | **短段问题**：383 ms 的真话打标成 `Tick-tock 0.75`、Speech 0.23 |
| 7 | 纯哼唱 8.5 s | （无语音） | 两段哼唱 VAD 判语音、打标 `Humming 0.27` / `Music 0.38`、ASR 幻觉日文 → 低置信标注 | 纯哼唱的 Humming 分数偏低（0.27 < 0.30），靠 gaps 文字里的 top 标签传达 |
| 8 | 说话压在音乐上 4.1 s | 「帮我听下这首歌是啥？」✅ conf 0.85 | `Music 0.96 + Speech 0.85` 同段 | 打标能同时给两个高分标签 |
| 9 | 中英 + 拟声 13 s | 三句对，拟声"biu biu"→「5五」、whoosh→「wosh」 | 6.11–6.66 打标 Speech 0.53 但 VAD 未判 → 补跑 ASR 得「.」 | 拟声词按预期错 |
| 10 | 长音频 58.6 s：指令 + 两段音乐 + 指令 | 三句指令全对 | 两段音乐 `Music 0.79 / 0.97`；5.12–6.85 VAD 漏、打标 Speech 0.98 → 补跑得「呀。」 | 984 ms 推理 / 58 s；折叠阈值 40 段未触发 |

### 由此改的规则（在 #1 的三条之上）

- **VAD 漏检补救**：VAD 判非语音、打标 `Speech ≥ 阈值` 的段也跑 ASR，gaps 注明"VAD 未判为语音，已补跑"。样本 #10 捞出的是「呀。」——内容不多，但不再静默丢。
- **低置信措辞只陈述事实**：原来写"可能是喷麦 / 呼吸"，在哼唱（#5、#7）和唱的音（#6）上是猜错的。改为"打标 Speech 仅 x（top 标签 分数）→ 文本置信度低"，段长 < 1 s 再加"打标在短段上本身也不可靠"。注入块同样把 top 标签给主模型。

### 观察

- **打标是判断"这段是不是话"最可靠的信号**，VAD 只负责切；两者不一致时都保留、都写出来。
- **clip 级 tagger 在 < 1 s 的段上不可靠**（#6 的「就是这个」）：这是模型限制，不是阈值问题。短段的低置信标注要让主模型看到段长。
- **纯哼唱的 `Humming` 分数只有 0.27–0.40**，比口哨（0.95）弱得多。`capabilities_available` 里 `pitch_transcribe` 的触发在 M2 按标签筛时要考虑这点（阈值或用 Music ∪ Humming ∪ Mantra）。
- 快速口语连读处 SenseVoice 会错（#5 后半），这是 ASR 本身的上限，便宜档不再调。

n = 10 / ≥ 10 ✅。

## 盲测（2026-09-21，n = 10）

方法同 T4：隔离模型实例（`claude -p --model sonnet`，空目录、无项目上下文），只给 `@mmp/client` 渲染的注入块 + 七项能力的一句话说明，问四件事：诉求是什么、处理哪个时间段、调哪个能力、哪些信息不可靠。原文见 [附录-T6-盲测原文.md](附录-T6-盲测原文.md)。

| # | 素材 | 诉求 | 时间段 | 能力 | 被幻觉 ASR 误导 |
|---|---|---|---|---|---|
| 1 | 口哨 + 扒谱指令 | ✓ | 1.09–18.59 ✓ | `pitch_transcribe` ✓ | 否——明确指出「あ.」「.」不可信 |
| 5 | 哼唱 + "在不在调上" | ✓（**从上下文纠正了 ASR 的错句**） | 5.66–8.19 ✓ | `pitch_transcribe` ✓ | 否 |
| 6 | "这个音是什么音高 [la]" | ✓ | 2.46–3.01 ✓ | `pitch_transcribe` ✓ | 否 |
| 7 | 纯哼唱 | 无 ✓，判为哼唱而非语音 | 0.74–7.14 ✓ | `pitch_transcribe` | 否 |
| 8 | 说话压在音乐上 "这首歌是啥" | ✓ | 2.05–4.12 ✓ | `music_id` ✓ | 否——「And？」被排除 |
| 10 | 长音频两首歌 | ✓ 两首 | 7.14–18.62 / 32.45–56.61 ✓ | `music_id` ×2 ✓ | 否 |
| 2, 3, 4, 9 | 纯指令 / 英文 / 中英混 / 音效知识提问 | 无或知识性 ✓ | ✓ | 不需要 ✓ | 否 |

**10 / 10：选对工具、指对时间段、零次被幻觉文本带偏。**

### 观察

- 低置信标注 + 打标证据（"Speech 仅 0.14，top Mantra 0.68"）足以让主模型自行排除幻觉、并把哼唱当哼唱处理；"不猜原因"的措辞没有造成困惑。
- gaps 里"夹在两段语音之间的短非语音"提示让模型偏谨慎：样本 2 对一个 351 ms 的正常停顿也建议 `transcribe_segment` 复核。这是诚实的代价，比漏掉一声口哨便宜；如果实际成本高，M3 的预算阶梯负责压。
- 模型反复索要的两样东西正是能力层该给的：音乐段的内容信息（`music_id` / `pitch_transcribe` 的产物）和正常语音段的 ASR 置信度（注入块目前只在低置信时显示，可考虑常显）。
