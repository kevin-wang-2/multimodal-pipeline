# 实施计划

> 2026-09-19 起。对象是 [架构.md](架构.md) 定稿后的 **M1 infra 骨架**；M2–M4 只给方向。
> 里程碑跟踪在内部 Gitea 的 issue 里，每个步骤一个 issue，编号与本文的 S0–S6 对应。本文是计划的唯一源头，issue 只是执行状态。

## 0. 计划原则

1. **先竖切，再横铺。** 每一步都交付一条能跑通的端到端路径，而不是先把某一层做完整。第一条路径是内网直连的音频预检，第二条是公网绑定的文档 OCR。
2. **协议先于代码。** A↔B 消息、任务 API、媒体句柄、digest、能力元数据五个 schema 先定稿并落成 JSON Schema，两种语言的实现都从它生成类型、对它做契约测试。改协议先改 schema。
3. **每步有验收，验收可自动化的进 CI。** 不能自动化的（例如"A 无公网监听"）写成手工检查清单，步骤关闭前执行一次。
4. **模型是插件，最后接。** S1 用一个 `echo` 任务类型把队列、缓存、句柄、API 全部验证完，再接真模型。
5. **B 保持无状态，不许长胖。** 任何"B 存一下就方便了"的需求都先问一遍能不能放 A 或 C。

## 2. 仓库布局（monorepo）

```
protocol/                 语言中立的唯一源头
  schemas/*.schema.json     ab-message / job-api / media-handle / digest / capability
  fixtures/                 契约测试样本（含 M0 的 digest）
  版本号在每个 schema 的 $id 里，A↔B 的 register 消息里带 protocol_version
node/                     A 算力节点（Python）
  mmp_node/                 队列、缓存、引擎池、注册表、句柄、ws 客户端
  mmp_broker/               B 的 Python 实现（绑定模式）
  engines/                  每个引擎一个子包，进程外运行（见 §4.2）
  pyproject.toml
ts/                       pnpm workspace
  packages/broker/          B 的 TypeScript 实现（绑定模式 + 独立模式）
  packages/client/          C：客户端包
  packages/adapters/openclaw/   首个适配层
docs/  tools/  testdata/  models/    现状不变
```

- Python：3.12，`pyproject.toml` + venv，不引入 conda 到仓库（GPU 机上引擎自己的 conda 环境由引擎子进程各管各的）。
- TypeScript：Node 22，pnpm workspace，`ws` 做 WebSocket，`ajv` 校验 schema，类型从 JSON Schema 生成。
- Python 侧用 pydantic 建模，契约测试确保 pydantic 模型与 JSON Schema 互相接受同一批 fixtures。

## 3. 步骤

每步给出：内容、产出、验收、依赖、规模（S / M / L，只表示相对大小）。

### S0 · 协议定稿

**内容**：把架构.md 里的骨架变成可执行的 schema，关掉两个开放问题（任务 API 细节、A↔B 协议细节）。要定的：

- A↔B 四类消息的信封：`{type, protocol_version, ts, payload}`；`register` 含 `node_id`、`node_key`、`capabilities[]`、`engine_versions{}`；`heartbeat` 间隔 10s，3 次未收视为断线；`request` / `response` 以 `req_id` 配对，B 侧在途超时默认 = 任务 `wait` + 5s。
- 重连：A 指数退避 1s → 60s，抖动 ±20%；重连即重新 `register`，B 用 `node_id` 覆盖旧表项。
- 取消：`DELETE /jobs/{id}` → `request{op: cancel}`；A 对排队中任务直接出队，对运行中任务尽力而为并回 `cancelled` 或 `done`。
- `job_id` 由 A 生成（`node_id` 前缀 + ULID），B 不生成 id，保证无状态。
- 错误码表：`backpressure`(429) / `no_node`(503) / `node_offline`(503) / `unsupported_type`(400) / `media_fetch_failed`(422) / `engine_failed`(500) / `timeout_degraded`(200，带 `source.degraded`)。
- 能力元数据 schema：架构.md §10 的 yaml 转 JSON Schema，加 `engine_version` 与 `tiers[]`。
- 媒体句柄 schema：架构.md §6；`inline` 上限 8MB，超过必须走 `get`。
- digest schema：架构.md §8 的示例转 JSON Schema，`label_status` 枚举、`null` 语义按 T4 观察③。

**产出**：`protocol/schemas/*.schema.json`、`protocol/fixtures/`、`docs/协议.md`（人读版，与 schema 同步）。
**验收**：M0 的 digest 样本通过 digest schema；fixtures 在 py（jsonschema）与 ts（ajv）两侧都通过；架构.md 的开放问题列表划掉两条。
**依赖**：无。**规模**：M。

### S1 · A 核心 + B-py 绑定模式 + CI

**内容**：不接任何模型，用 `echo` 任务类型（原样返回 media 的 hash 与 params，可配置 sleep）把 infra 全部做出来：

- 队列：asyncio 优先级队列，`interactive` > `batch`；每任务类型的并发上限与 VRAM 预算由注册表声明；队列长度上限 → 429；任务键去重合并。
- 缓存：SQLite（标准库），键 = (hash, type, tier, engine_version, params 规范化 hash)；命中返回 `cached: true`。
- 媒体句柄：`inline` / `get` / `put` 三种取放；hash 在取到字节后算。
- 注册表：任务类型元数据 + 引擎绑定；`/capabilities` 从它生成。
- B-py 绑定模式：在 A 进程内起 HTTP（FastAPI），只绑内网地址，实现 §5 全部端点；A↔B 消息在进程内直接调用，但走与 ws 相同的信封与分发函数，为 S4 复用。
- 配置：单个 `node.toml`，环境变量覆盖；所有阈值外置。
- CI：Gitea Actions，两个 job：`unit`（任意 runner，py + ts 单测与契约测试）、`gpu`（打 `gpu` 标签的 runner，S2 起跑真模型冒烟）。

**产出**：可运行的 A + B-py，`curl` 能提交 `echo` 任务。
**验收**：并发提交 100 个 `echo`，优先级顺序正确；队列超限得 429；同参数重复提交第二次 `cached: true`；`inline` 与 `get` 提交同一文件得到相同 `media_id`；CI 绿。
**依赖**：S0。**规模**：L。

### S2 · `triage.audio` 引擎

**内容**：把 M0 的三件套（Silero VAD + Zipformer 打标 + SenseVoiceSmall int8）做成第一个引擎插件，按 §4.2 的方式跑在子进程里。同时修掉 M0 留下的问题：

- schema 修正落地：置信度阈值 0.30、`label_status`、去掉 `caption`、`null` 语义（T4 观察②③）。
- VAD padding：切点误差目标 < 50ms（T2 的 0.18s 吞字问题）。
- `gaps` 由规则生成，与打标质量解耦。

**产出**：`node/engines/triage_audio/`，注册为 `triage.audio`，tier `cpu`。
**验收**：M0 素材产出的 digest 通过 schema，且与 T4 盲测用的那份在结构上一致（段边界、gaps 两条）；VAD 切点在 2.00 ± 0.05s；26s 素材端到端 ≤ T2 的 1.5×；`gpu` job 里用真模型跑一次冒烟。
**依赖**：S1。**规模**：M。
**并行项**：T6 真实音频复验（Q11）。用真人哼唱 + 真人口述录 ≥ 10 段，跑 T3/T4 流程，盲测 n ≥ 10。这是 M0 验收的欠账，不阻塞 S2 但阻塞 M1 关闭。

### S3 · C-ts + OpenClaw 适配层（内网端到端）

**内容**：

- `packages/client`：`submit / wait / poll / cancel / capabilities`，类型来自 schema；错误码映射成异常类型；不知道也不关心 B 在哪。
- digest → 注入块：确定性模板，带边界标记，含 `source` 与降级标注。
- OpenClaw 适配层：`message_received` 触发提交，`before_prompt_build` 注入；服务不可用 / 超时 → 平台转写兜底并显式标注降级；关闭平台自动转写。
- 实测多插件 `prependContext` 合并语义（架构.md 开放问题），结论写进 docs。

**产出**：`ts/packages/client`、`ts/packages/adapters/openclaw`。
**验收**：M1 定义第 1 条；关掉 A 后 OpenClaw 仍能回复且注入块标注降级；同一媒体连续追问 5 轮不重复推理。
**依赖**：S1（S2 完成前可用 `echo` 联调）。**规模**：M。

### S4 · A↔B WebSocket + B-ts

**内容**：

- A：ws 客户端，出站连接、`register`、心跳、重连退避、多 B 同时连接；进程内分发函数与 S1 共用。
- B-ts：ws 服务端（认证、注册表、在途映射、路由）+ 任务 API 的 HTTP 端点；绑定模式（作为库嵌入宿主进程）与独立模式（单独进程）同一份代码，只差入口。
- 认证：静态密钥，配置下发；`register` 校验失败直接断开。

**产出**：`node/mmp_node/ws_client.py`、`ts/packages/broker`。
**验收**：M1 定义第 5、6 条；A 在 NAT 后连到公网测试宿主上的 B-ts，`echo` 任务往返成功；B-py 与 B-ts 对同一批 fixtures 行为一致（同一套契约测试跑两个实现）。
**依赖**：S0、S1。可与 S3 并行。**规模**：L。

### S5 · `ocr.structured` 引擎（GPU）+ 公网端到端

**内容**：

- 引擎插件：PP-OCRv6 作快档（tier `gpu-fast`）、PaddleOCR-VL 作慢档（tier `gpu`）；VRAM 预算在注册表声明（VL 12GB → 并发 1）；按需装卸，预热窗口可配。
- 升级触发（T5 §4.2）第一版只做两条：低置信行占比、覆盖率异常；粒度按页。
- 公网 agent 宿主侧：宿主签 presigned GET/PUT → C-ts 提交 → 结果 PUT 回句柄。
- 环境：GPU 机上的引擎 conda 环境按 T5 §6 的坑位清单建，写成脚本。

**产出**：`node/engines/ocr_structured/`，注册为 `ocr.structured`。
**验收**：M1 定义第 2、4 条；T5 的发票 3 张字段全对；VL 并发 2 提交时第二个排队而非 OOM。
**依赖**：S1、S4。**规模**：L。

### S6 · M1 收口

**内容**：跑一遍 §1 全部条目；手工检查清单（端口扫描、拔线）执行并记录；写 `docs/结果-M1.md`；架构.md 与 README 状态更新；Gitea 里程碑关闭。

## 4. 横切决定

### 4.1 测试分层

| 层 | 内容 | 跑在哪 |
|---|---|---|
| 契约 | fixtures 过两种语言的 schema 校验；B-py 与 B-ts 对同一批请求给同一批响应 | `unit` job |
| 单元 | 队列顺序 / 背压 / 去重、缓存键、句柄取放、注入模板 | `unit` job |
| 冒烟 | 真模型跑 M0 素材，检查 digest 结构与耗时上限 | `gpu` job |
| 端到端 | M1 定义的 7 条 | 手工 + 脚本，S6 执行 |

M0 的合成素材是 golden fixture；真实音频（T6）进来后加第二组。

### 4.2 引擎跑在子进程

每个引擎是 A 管理的子进程，JSON-lines 走 stdio。理由：

- 显存释放唯一可靠的方式是结束进程；"卸载"= kill。
- sherpa-onnx、paddle、whisper.cpp 依赖互相打架的概率高（T5 已踩 oneDNN 与 nvjitlink 的坑），进程隔离比 import 隔离省心。
- 引擎崩溃不带走 A。

代价是每个引擎多一层协议，用同一份小型 `engine-io` schema 解决。CPU 便宜档也走子进程，不搞特例。

### 4.3 配置与版本

- 三个角色各一个配置文件（`node.toml` / `broker.toml` / 适配层的宿主配置），所有阈值、密钥、地址外置。
- `protocol_version` 在 register 里协商，不兼容直接拒绝并给明确错误。
- `engine_version` 进缓存键，升级引擎自动失效旧缓存。

### 4.4 可观测

- 每任务：`timings_ms` 分阶段、tier、是否降级、是否命中缓存，结构化日志一行。
- 心跳：队列长度、VRAM 余量、已装载引擎。
- M1 不做指标后端，日志落文件即可。

## 5. 风险

| 风险 | 对策 |
|---|---|
| Windows 上 Python 包与 CUDA 依赖的安装坑（T5 记了 4 条） | 引擎各自 conda 环境 + 子进程隔离；安装脚本化并进 CI 的 `gpu` job |
| 真实音频上打标质量与合成素材差异大（T3 已见 `Dog`） | T6 与 S2 并行；路由只用粗类别 + 阈值，`gaps` 不依赖标签 |
| B 在实现中不知不觉长出状态 | 契约测试里加"重启 B 后一切照旧"用例；code review 以 §0 第 5 条为准 |
| 跨国 ws 长连接抖动 | 已有同类实测；S4 验收含断线重连；C 的重试是默认行为 |
| 显存争抢 | 注册表声明 VRAM 预算，调度器按预算串行；S5 验收含并发 OOM 用例 |
| 协议定早了要改 | schema 带版本；S2/S3 先用内网线暴露问题，S4 前允许改 |

## 6. M2–M4 方向

M2 与 M3 的性质和 M1 不同：**能做就做，不能做放着也行**。M1 是骨架，每条都必须过；M2 / M3 是往骨架上挂零件，每个零件先调研（SOTA 候选、Windows + conda 能否跑、小样本实测）再下"集成 / 不集成 / 延后"的结论，"延后"也是合格产出。

### M2 能力层（2026-09-22 立项，里程碑 `M2`，issue #12–#21）

骨架一项 + 九条调研线。每条线的 issue 正文带同一份模板：候选 ≥ 2、输入粒度与输出 schema、`consumes` 触发条件、T6 素材实测、结论 + tier + VRAM。

| issue | 线 | 零件 | 难度 |
|---|---|---|---|
| M2-0 | 骨架 + 透传（工程） | `consumes.labels` 筛 `capabilities_available`；能力任务带 `start/end`；`@mmp/client.describe(id)`；OpenClaw tool；tagger 乐器标签与 SenseVoice 情绪 / 事件透传；`audio_qc`（削波 / 喷麦 / LUFS，确定性）进 gaps | 低 |
| M2-1 | 分离 | `source_separate`（Demucs / BS-RoFormer）——A 组一半零件的前处理 | 低 |
| M2-2 | 单音扒谱 + 量化基准 | `pitch_transcribe`、`key_tempo_beat`、`score_render`（MIDI → 谱，确定性） | 低 |
| M2-3 | 多轨扒谱 | `music_transcribe`（端到端 AMT vs 分离流水线）、`drum_transcribe`、`melody_extract` | **高** |
| M2-4 | 和声与结构 | `chord_recognize`、`structure_segment` | 中 |
| M2-5 | 乐器与音色 | `instrument_recognize`；`timbre_describe` 分"可描述 / 可复现（合成器参数反推）"两档 | 中 / **高** |
| M2-6 | 语音贵档与增强 | `transcribe_segment`、`lyrics_transcribe`、`denoise` | 低 |
| M2-7 | 说话人 | `speaker_diarize`（做）、`speaker_identify`（只调研；声纹数据是产品 / 合规决定） | 中 |
| M2-8 | 描述与标签 | `audio_describe`、`music_describe`、`music_tag` | 中 |
| M2-9 | 识别 | `music_id`、`cover_id`——大概率延后或 remote tier | 中（工程） |

顺序：0 → 1 → 2 → 3 → 6 → 7 → 5 → 4 → 8 → 9。M2-3 / M2-5 / M2-7 需要 T6 之外的新素材（多乐器混音、合成器音色、多人对话）。

- **M3 预算与反馈**：升级触发（显式 / 隐式）、升级次数上限、来源标注；引擎档位回落的延迟阈值定数。同样能做就做。
- **M4 模态同构**：`triage.image`（版面粗分 + 快档 OCR）、视频抽帧递归；文档腿的 bbox 与异步升级两个开放问题在这里定。
