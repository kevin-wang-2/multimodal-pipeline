# ts 包的发布与安装

三个包：`@mmp/protocol`（schema + 类型 + 校验器）、`@mmp/broker`（B-ts）、`@mmp/client`（C 客户端）。

## 为什么是自建 registry

- 内部 Gitea 的 npm registry 只在 tailnet 里，而境外服务器不允许进 tailnet；
- 项目早期，不发 npmjs；
- prod / dev 两台服务器和多位开发者都要装，tgz 手传不可持续。

所以在枢纽机上跑一个 **Verdaccio**（PM2 `mmp-npm`，只监听 127.0.0.1:4873），由 nginx 挂在 `https://mmp.seanartech.com/npm/`。它**只服务 `@mmp/*`**，不代理 npmjs：其他包照常走公网 registry。**匿名可读**（代码本来就是公开的），发布要账号；不开自助注册。

## 安装（消费方）

项目根 `.npmrc` 一行，可以提交进仓库：

```ini
@mmp:registry=https://mmp.seanartech.com/npm/
```

然后 `pnpm add @mmp/client`（或 npm / yarn）。不需要任何凭据。

## 发布

- 手动：`ts/` 下 `pnpm -r build && (cd packages/<p> && pnpm publish --no-git-checks)`，用户级 `~/.npmrc` 里放 `//mmp.seanartech.com/npm/:_auth=<base64("mmp-publisher:<密码>")>`（**不要提交进仓库**）。
- CI：`.gitea/workflows/release-npm.yml`，手动触发或推 tag `npm-v*`；用仓库 secret `MMP_NPM_AUTH`。
- 版本以各包 `package.json` 为准，同版本重发会被拒（E409），先 bump。`@mmp/protocol` 的版本跟协议版本走（1.1.x）。

## 枢纽机上的文件

| 路径 | 内容 |
|---|---|
| `~/mmp/verdaccio/config.yaml` | registry 配置（scope、ACL、`url_prefix: /npm/`） |
| `~/mmp/verdaccio/htpasswd` | 发布账号（bcrypt）；加人：`htpasswd -bB htpasswd <user> <pw>`，然后在 config 的 `publish` 里加用户名 |
| `~/mmp/verdaccio/storage/` | 包存储 |
| `~/mmp/verdaccio/ACCOUNTS.txt` | 发布账号 `mmp-publisher` 的密码（600，仅管理员） |
| `/etc/nginx/sites-enabled/mmp` | `location /npm/` |
