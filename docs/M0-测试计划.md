# M0 测试计划

> 2026-09-10 起。目的：在写服务代码之前，先用最小代价把 PRD 里的关键假设**测出来**。
> 所有结论回写 `docs/架构.md`（开放问题与实测索引）。

## 测试素材

`tools/make_test_clip.py` 生成一段 4 秒的合成测试音频，精确复现 PRD 里的关键场景：

```
[00:00–02:00] 无伴奏人声哼唱（合成的旋律，非语音）
[02:00–04:00] 口述指令「帮我把这段的谱子扒出来」
```

用途：
1. **验证预检全时长原则**——意图藏在第 2 段，却要作用于第 1 段；
2. 作为 ASR 基准的固定输入（可重复）；
3. 作为 M0「agent 能否选对工具」的题目。

> ⚠️ 这是**合成素材**，只能验证管线机制，不能代表真实域外音频（剧场/水声）的识别难度。真实样本要另外补。

## T1 · GPU 机器 ASR 实力基线 ← 回答 Q2（L1-plus 的预算）

| 项 | 内容 |
|---|---|
| 目的 | 那台 5070 Ti 跑 ASR 到底多快、冷启动多久、吃多少显存 |
| 方法 | whisper.cpp（CUDA 构建）跑 `large-v3-turbo` 与 `base`，同一素材取多次 |
| 记录 | 模型加载时间（冷启动）、encode/decode 耗时、RTFx、峰值显存、与 `--no-gpu` 的 CPU 对照 |
| 成功判据 | 拿到冷启动耗时与 RTF 数字 → 据此定 L1-plus 的**延迟预算**与"值不值得升" |
| 阻塞 | 该机 github 不通 → 二进制经 Mac 中转；模型走 hf-mirror 镜像 |

## T2 · Mac 本地 floor 可行性 ← 回答 Q2（L1-floor 的预算）

| 项 | 内容 |
|---|---|
| 目的 | 本地常驻的小模型（SenseVoiceSmall / faster-whisper-small）在 Mac 上跑这个素材要多久 |
| 记录 | 冷启动、RTF、CPU/内存占用 |
| 成功判据 | 判断"本地 floor 是否真的够快"，以及 Mac 是否承受得住常驻 |

## T3 · AED 时序路由验证 ← 回答 Q3 + 旧稿待办

| 项 | 内容 |
|---|---|
| 目的 | 验证 frame-level SED 能否把「哼唱段 / 语音段」正确切开 |
| 方法 | EfficientAT-M2（30M）或 PANNs CNN14 出逐帧标签，看置信度曲线能否在 2.0s 处切换 |
| 成功判据 | 切点与真值偏差 < 0.5s（SED 帧粒度），且 `Humming`/`Music`/`Speech` 三类可分 |

## T4 · M0 端到端手工验证 ← 定死 digest schema

| 项 | 内容 |
|---|---|
| 目的 | 手工串「SED → ASR → 拼 digest → 交给 agent」，看上层能否选对工具 |
| 判据 | agent 能识别「要处理的是 00:00–02:00 的哼唱段」并调用扒谱类工具；digest 里无任务相关结论 |
| 产出 | digest schema 定稿 |
